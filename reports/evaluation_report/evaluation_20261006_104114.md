<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism
  - ML systems: deterministic. For a given row / same input the model returns the same output every time (example: a regression that always returns 10 for that input). ML uses fixed labels and one moving component (the model).  
  - LLM apps: probabilistic and non-deterministic. The same input can give different outputs over time. Semantic equivalence matters (text can differ but be acceptable), so exact matching is not enough. Evaluation requires human judgment and detailed reports.

- Dynamic cost
  - ML systems: cost is predictable per data batch. Example in the context: 100 rows always consumes the same compute / cost (e.g., "10 rupees") each time.  
  - LLM apps: cost is dynamic and hard to fix. Both input length and output length vary. Compute (and cost) changes with input, output and retrieved context. You must keep headroom because outputs can be shorter or longer than a set maximum.

- Input-output tracking
  - ML systems: generally you do not have to track the entire input→output journey because there is typically no workflow; evaluation is automated via mathematical formulas.  
  - LLM apps: you must manage the relationship between input and output because nothing is static. Multiple components (e.g., retriever + LLM/generation) interact, so tracing the end-to-end journey and judging outputs is needed and more costly.

Not covered in the context: concrete methods, tools, or best practices to implement tracking, cost controls, evaluation pipelines, or exact metrics to measure and limit variability.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>

Also, software testing mostly checks **correctness only**, while LLM evals need **multi-metric quality checks** like:
