- **Input:** How do offline vs online evals differ in pre-release gating, drift detection, timing, cost, regression?
- **Actual Output:** I don't know.
- **Expected Output:** Offline and online evals serve different but complementary purposes:

- **Pre-release gating**: **Offline eval** is used before deployment as a release gate—if the score is above a threshold, you deploy; otherwise, you don’t. **Online eval** happens after deployment, so it does not gate releases.
- **Drift detection**: **Online eval** detects drift, surprises, and emergent bugs in live production. **Offline eval** does not detect drift because it uses a fixed golden dataset.
- **Timing**: **Offline eval** runs before deployment on anticipated inputs. **Online eval** runs continuously after deployment on real, unanticipated production traffic.
- **Cost**: **Offline eval** is fast, cheap, and repeatable since it runs on a small dataset. **Online eval** can be expensive at scale, so sampling is used (e.g., monitoring 1,000 out of 50,000 conversations).
- **Regression**: **Offline eval** is well-suited for regression testing—ensuring a change doesn’t break other parts of the application. **Online eval** focuses more on live performance and normalcy rather than regression.

In short: offline eval checks if your application is working correctly; online eval checks if it is working normally in production.

</details>
