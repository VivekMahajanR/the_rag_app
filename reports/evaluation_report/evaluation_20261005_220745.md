<details><summary><b>View Test Case Data</b></summary>

- **Input:** How do ML systems and LLM apps differ in determinism, dynamic cost, and input-output tracking?
- **Actual Output:** - Determinism
  - ML systems: deterministic. Same input (e.g., a row with fixed features) gives the same output every time (regression returns fixed continuous value). Software behavior is fixed and repeatable.
  - LLM apps: probabilistic and non-deterministic. The same input can produce different outputs across runs. The LLM and other moving parts make results variable.

- Dynamic cost / compute
  - ML systems: compute/cost is stable for a given workload. Example in the context: giving 100 rows to a hosted ML model consumes x units of compute each time.
  - LLM apps: compute and thus cost are dynamic. Compute changes with the input, the output, the retrieved context, and other components (retriever, vector DB). Usage and cost vary with those factors.

- Input→output tracking (workflow and evaluation)
  - ML systems: prediction is immediate and simple. Generally you only evaluate the model itself with mathematical formulas. You usually do not track a long input-to-output workflow. Evaluation is cheaper and more automated.
  - LLM apps: there is a workflow with multiple components (LLM, retriever, vector DB, etc.). Workflow length and complexity vary. You must manage the relationship between input and output because things are dynamic. Evaluation requires human judgment and detailed reports; there is no single correct answer.
- **Expected Output:** ML systems are generally deterministic: the same input row gives the same output every time, with fixed compute/cost for that input size.  

LLM apps are probabilistic and dynamic: the same input can produce different outputs, and both cost and compute vary because input length, output length, and retrieved context all change.  

Also, ML prediction usually has a simple input-to-output flow, while LLM apps often require tracking the full journey from input through retrieval, prompting, and output.

</details>
